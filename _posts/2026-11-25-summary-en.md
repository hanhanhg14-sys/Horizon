### [OpenAI Preprint Claims Exact Matrix Multiplication Exponent 9/4](https://github.com/openai/math/blob/main/preprints/The-matrix-multiplication-exponent-is-nine-fourths-November-24-2026/paper.pdf) ⭐️ 9.0/10

An OpenAI Math preprint claims that the matrix multiplication exponent is exactly 9/4 \(Θ\(n^2.25\)\) over every field, refuting the conjecture that the exponent equals 2. Commenters note the new contribution is the Ω\(n^2.25\) lower bound, since the O\(n^2.25\) upper bound was already known. The result is a preprint and has not been independently verified.

hackernews · E-Reverance · Nov 25, 01:19 · [Discussion](https://news.ycombinator.com/item?id=50637220)

The current paper adds a matching lower bound Ω\(n^2.25\) for every field, turning that upper bound into the exact exponent Θ\(n^2.25\).

**「Impact」** If the lower bound is confirmed, it would settle the exponent question at Θ\(n^2.25\) and rule out the long-standing goal of O\(n^2\) algorithms for general matrix multiplication. Until peer review, the claim should be treated as unverified.

### [CVE-2022-22965 Spring Framework RCE PoC published with active attacks](https://cve.now/CVE-2022-22965) ⭐️ 9.0/10

CVE-2022-22965 is a remote code execution vulnerability in Spring Framework that affects Spring MVC or Spring WebFlux applications on JDK 9 or later via data binding. A proof-of-concept exploit has been published on GitHub, and the known exploit requires a non-default setup where the app is deployed as a WAR on Tomcat rather than as a Spring Boot executable jar. The flaw is listed in CISA&\#x27;s Known Exploited Vulnerabilities catalog, indicating active attacks.

rss · cve.now 新收录的 CISA KEV · Nov 25, 02:11

**「Background」** Spring Framework automatically binds HTTP request parameters to Java object properties, which can be exploited if an attacker can reach sensitive class fields through parameter names. The vulnerability is specific to applications running on JDK 9 or later and deployed as a WAR file on Tomcat, rather than as a Spring Boot executable jar.

**「Impact」** Operators running affected Spring applications as WAR files on Tomcat should apply the vendor patch or upgrade immediately; the unauthenticated RCE path is exploitable in the non-default WAR deployment and the flaw is being actively exploited.

### [Active intrusion campaign targets Check Point security management servers via V8 PRNG flaw](https://www.greynoise.io/blog/check-point-security-management-servers-intrusion-campaign) ⭐️ 8.0/10

GreyNoise reports an active intrusion campaign against Check Point security management servers. Attackers repeatedly called the HFS loginSrp1 endpoint to collect signed session cookies with &\#x27;sid&\#x27; values generated by JavaScript&\#x27;s Math.random\(\), reconstructed the V8 PRNG state to recover the HFS session-cookie signing key, and then forged a signed admin session cookie. The report&\#x27;s discussion suggests CVE-2026-16232 may have provided initial access, though one commenter notes the exact initial access vector is unclear.

hackernews · louiereederson · Nov 24, 16:32 · [Discussion](https://news.ycombinator.com/item?id=50630594)

**「Background」** Check Point&\#x27;s support note SK185169 documents CVE-2026-16232, an authentication bypass in the SmartConsole login process that allows an unauthenticated remote attacker to obtain an application login token and authenticate with full administrative privileges when the management server is reachable from the internet and Trusted Clients are unrestricted. The NVD entry lists the same vulnerability details; it is separate from the V8 Math.random\(\) session-cookie weakness described in the current report, but may represent the initial access vector that exposed Check Point management servers to the later exploitation.

**「Impact」** Administrators of Check Point security management servers should audit whether their management interfaces are exposed to the internet and review session logs for forged admin cookies, since the campaign bypasses authentication by using attacker-signed admin session cookies on affected HFS-based management servers.

**「Community Discussion」** Commenters debated the initial access vector: omh said it is unclear how attackers first gained entry and pointed to CVE-2026-16232, asking whether organizations exposed Check Point management servers to the internet. 20after4 argued the root issue is that Math.random\(\) should provide security-relevant randomness rather than relying on each application to avoid it.

### [WSO2 CVE-2022-29464 File Upload RCE PoC and Exploit Available](https://cve.now/CVE-2022-29464) ⭐️ 8.0/10

CVE-2022-29464 is an unauthenticated remote code execution flaw in several WSO2 products, including API Manager, Identity Server, and Enterprise Integrator. Attackers can send a crafted request to the /fileupload endpoint to upload arbitrary files, such as a malicious JSP, to a chosen server location and execute code. Public exploit code, including a Metasploit module, has been published on GitHub, and the vulnerability is listed in CISA&\#x27;s Known Exploited Vulnerabilities catalog.

rss · cve.now 新收录的 CISA KEV · Nov 25, 02:21

**「Vendor advisory and fix timeline」** WSO2&\#x27;s advisory WSO2-2021-1738 described the flaw as improper validation of user input that allows an arbitrary file to be uploaded to a user-controlled location and then used for remote code execution. The vendor reported providing temporary mitigations in January 2022 and delivering fixes for supported product versions in February 2022; the current update highlights the later publication of public proof-of-concept and Metasploit exploit code.

**「Impact」** Administrators of affected WSO2 deployments should apply vendor patches or mitigations and check for signs of exploitation, because unauthenticated attackers can use the published Metasploit module against unpatched systems.

### [Apache APISIX CVE-2022-24112 Bypass Actively Exploited, PoC Published](https://cve.now/CVE-2022-24112) ⭐️ 8.0/10

Apache APISIX \(CVE-2022-24112\) lets attackers overwrite the client IP through the batch-requests plugin&\#x27;s X-REAL-IP header, bypassing the Admin API IP restriction. In default setups that still use the default API key, this leads to remote code execution; otherwise the data panel IP restriction can still be bypassed. The vulnerability is reachable remotely without authentication, is being exploited in attacks, and a proof of concept has been published on GitHub.

rss · cve.now 新收录的 CISA KEV · Nov 25, 02:11

**「Background」** Apache APISIX is an API gateway whose Admin API is commonly restricted to trusted IP addresses. The batch-requests plugin processes multiple requests in one call, and the flaw allows an attacker-supplied X-REAL-IP header to overwrite the address used for that IP restriction.

**「Impact」** Because exploitation is already occurring, operators of default Apache APISIX configurations with the default API key are at immediate risk of remote code execution and should audit for unauthorized Admin API access.

**Tags**: `#security`, `#Apache APISIX`, `#CVE-2022-24112`, `#remote code execution`, `#vulnerability`
